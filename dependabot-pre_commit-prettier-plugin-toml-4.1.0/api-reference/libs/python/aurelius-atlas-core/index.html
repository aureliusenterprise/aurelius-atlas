  • Architecture
    • Architecture Decisions
      • ADR Template
      • 001. Keep one monorepo for every stack
      • 002. Modules are removable as whole slices
      • 003. Every project documents itself
      • 004. One shared domain model serves streaming and storage
      • 005. Development infrastructure starts with the app that needs it
      • 006. The whole system runs on one machine
      • 007. One shared identity provider serves every authenticated surface
      • 008. Real secrets are encrypted; only dev defaults are committed
      • 009. Every example runs and is tested, or it is removed
      • 010. The unit validated is the unit that ships
      • 011. The development environment is a versioned artifact
      • 012. Validation runs against real services, not substitutes
      • 013. Services prove who they are at every boundary
      • 014. The gate that refuses a change is defined once
      • 015. A change answers for what it caused; the state of the world is reviewed on a cadence
      • 016. The system observes itself; its operational data never leaves it
      • 017. Shared concepts change only in ways that keep readers working
      • 018. Settings arrive at startup through one channel and fail loudly
      • 019. The system releases as one versioned whole
      • 020. Dependencies stay current by default; majors move by decision
      • 021. A new technology joins the system by recipe
      • 022. The codebase explains itself to the agents that change it
      • 023. A storage schema changes only by recorded migration
      • 024. A validated release is promoted by a declared path
      • 025. Data has a stated lifetime that the system enforces
      • 026. The system can be brought back from a named snapshot
      • 027. Every stream carries a stated delivery guarantee
      • 028. Operational secret handling has a named owner and a rehearsed path
      • 029. What ships is signed, and its origin can be proven
      • 030. Interfaces between parts are verified, not assumed
      • 031. Language and runtime versions have a declared support window
      • 032. Shared streams are named by a declared convention
      • 033. Shipped artifacts carry a contents inventory
      • 034. Signals meet at one replaceable collection point
      • 035. Parts hand work to each other through a durable event log
      • 036. The delivery plane is a named exception to the data boundary
      • 037. The system itself promises nothing about staying up
      • 038. What a person may do is decided in one place, apart from who they are
      • 039. Data is protected where it travels and where it rests
      • 040. The system raises its hand when it is broken
      • 041. A failure of the running system has an owner and a rehearsed path
      • 042. Every dataset has an owner who answers for it
      • 043. AI-assisted review informs the two signatures
      • 044. Every change carries two human signatures
      • 045. Conventions are borrowed before they are invented
      • 046. The catalogue keeps its public contract
      • 047. One search store is the system of record
      • 048. Behaviour is proven against the reference
      • 049. Every function and rule is traceable to a test
      • 050. The system carries only what the catalogue needs
      • 051. The conversion proceeds in specified increments
      • 052. Behaviour is specified by scenarios read from the reference source
      • 053. The webapp is rewritten in Angular idiom, slice by slice
      • 054. The server API is the webapp's one data plane
      • 055. The lineage chain is a named data surface
      • 056. Behaviour is proven by executed tests

aurelius-atlas-core¶

Atlas stores and services for Aurelius Atlas (DD-002). Since increment 1.4: the typedef store, which keeps type definitions in one Elasticsearch document and serves them from the type registry. Since 1.5: Apache Atlas's built-in models and their typedef patches, loaded at start-up. Since 1.6: the store's reads and the search of /v2/types/typedefs. Since 2.2: the entity store, which keeps each entity as one Elasticsearch document, reserves unique attribute values and writes several entities all or nothing through a journal (DD-043 to DD-048).

store = TypedefStore(TypeRegistry(), ElasticsearchTypedefDocument(elasticsearch_store.client))
await store.load()  # every stored definition into the registry
created = await store.create_types_def(types_def)
await store.refresh()  # pick up another process's change (at most every 5 s)
await ModelLoader(store).load(BUILTIN_MODELS_DIR)  # addons/models of Atlas 2.4.0, and their patches
store.get_by_name("hive_table")  # the registered definition, as resolution completed it
search_types_def(store.registry, TypeSearchFilter.from_query([("type", "ENTITY")]))  # each kind sorted by name
