      • 015. A change answers for what it caused; the state of the world is reviewed on a cadence
      • 016. The system observes itself; its operational data never leaves it
      • 017. Shared concepts change only in ways that keep readers working
      • 018. Settings arrive at startup through one channel and fail loudly
      • 019. The system releases as one versioned whole
      • 020. Dependencies stay current by default; majors move by decision
      • 021. A new technology joins the system by recipe
      • 022. The codebase explains itself to the agents that change it

      • 026. The system can be brought back from a named snapshot

aurelius-atlas-dsl¶

The Atlas DSL for Aurelius Atlas, without I/O (DD-002). Since increment 4.3: a query parsed by Atlas's own grammar, with Atlas's syntax errors, into a typed syntax tree; and the clauses, limit and offset it asks for. The parser is generated by ANTLR from Atlas's AtlasDSLLexer.g4 and AtlasDSLParser.g4, unchanged (DD-240).

from aurelius_atlas_dsl.atlas_dsl import QueryMetadata, parse

query = parse("hive_table where name = 'sales' select name limit 10")  # raises AtlasError INVALID_DSL_QUERY
query.sources[0].where.expr.comp_e.operator  # Operator.EQ
QueryMetadata.of(query).resolved_limit  # 10

Installation¶

dependencies = ["aurelius-atlas-dsl"]

[tool.uv.sources.aurelius-atlas-dsl]
workspace = true

aurelius_atlas_dsl.dsl_tree ¶

The Atlas DSL's parse tree as typed, immutable nodes (DD-241).

One node per rule of AtlasDSLParser.g4 that DSLVisitor reads, named after it; a rule that only chooses (literal, atomE, compE, fromSrc, singleQrySrc) is the union of its alternatives, and querySrc, selectClause, limitClause and offsetClause are folded into their parent. Every node keeps text, the rule's getText(): its tokens joined without the spaces and comments the lexer skipped (DSL-05).
