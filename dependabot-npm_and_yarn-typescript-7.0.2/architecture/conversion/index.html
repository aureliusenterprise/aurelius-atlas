Conversion¶

Aurelius Atlas re-implements Apache Atlas 2.4.0 in Python with Elasticsearch 9 as its only store, keeping the REST API and the dashboard (ADR 046, ADR 047). The work proceeds in increments (ADR 051); this page is the roadmap and the status of each one.

The ledger in this section is the central record of the conversion:

Page What it holds
Design Log Numbered technical decisions (DD-NNN), never edited once accepted
Java to Python Map Which Java module or class becomes which Python module, and its status
Deviations from Apache Atlas Every intended behaviour difference, referenced by the parity report
Spec Map Which project's specs/ holds each increment
Increments The specifications written before the per-project move, as history

Definition of done for an increment¶

graph LR
    S[Semantics spec] -->|PR| C[Code + scenarios]
    C -->|parity + trace green| R[Two approvals]
    R -->|merged| D[Done]
    D -.->|records| L[Design log, Java map, deviations]

An increment is specified before it is built and proven before it is accepted (ADR 051). The checks a PR must pass:

  • Semantics spec in <project>/specs/N-M-slug/ (the Spec Map says where), every rule has an id
  • Every new public function has a test that names it (@pytest.mark.covers)
  • Every rule id is named by at least one test
  • Parity scenarios for the endpoints in scope pass, each citing its Atlas source (ADR 052)
  • nx affected -t lint typecheck test e2e -c ci is green and the coverage gate holds
  • Design log, Java map and deviations updated; ADR written if a business-level decision was made
  • Conventional-commit title and two human approvals

After phase 0¶

Two expat CVEs and a musl CVE are accepted on a temporary basis

CVE-2026-77214 and CVE-2026-102633 (expat/libexpat 2.8.5-r1, from the server image's hardened base) are fixed upstream in 2.9.0-r0 but accepted in SonarCloud because no hardened base image carried the fix yet; so is CVE-2026-107891 (musl 1.2.6-r2, from the webapp image's hardened base, fixed in 1.2.6-r3). The acceptance expires with the next base-image refresh — the checklist below is the re-decision, and an accepted risk that nobody re-checks is drift.
