# Conversion

Aurelius Atlas re-implements Apache Atlas 2.4.0 in Python with Elasticsearch 9 as its only store, keeping the REST API and the dashboard ([ADR 046](<https://aureliusenterprise.github.io/refactor-webapp-lineage-promote/architecture/adr/046-the-catalogue-keeps-its-public-contract/index.md>), [ADR 047](<https://aureliusenterprise.github.io/refactor-webapp-lineage-promote/architecture/adr/047-one-search-store-is-the-system-of-record/index.md>)). The work proceeds in increments ([ADR 051](<https://aureliusenterprise.github.io/refactor-webapp-lineage-promote/architecture/adr/051-the-conversion-proceeds-in-specified-increments/index.md>)); this page is the roadmap and the status of each one.

The ledger in this section is the central record of the conversion:

| Page | What it holds |
| --- | --- |

| [Java to Python Map](<https://aureliusenterprise.github.io/refactor-webapp-lineage-promote/architecture/conversion/java-map/index.md>) | Which Java module or class becomes which Python module, and its status |
| [Deviations from Apache Atlas](<https://aureliusenterprise.github.io/refactor-webapp-lineage-promote/architecture/conversion/deviations/index.md>) | Every intended behaviour difference, referenced by the parity report |
| [Spec Map](<https://aureliusenterprise.github.io/refactor-webapp-lineage-promote/architecture/conversion/spec-map/index.md>) | Which project's `specs/` holds each increment |
| [Increments](<https://aureliusenterprise.github.io/refactor-webapp-lineage-promote/architecture/conversion/increments/index.md>) | The specifications written before the per-project move, as history |

## Definition of done for an increment

```
graph LR
    S[Semantics spec] -->|PR| C[Code + scenarios]
    C -->|parity + trace green| R[Two approvals]
    R -->|merged| D[Done]
    D -.->|records| L[Design log, Java map, deviations]
```

An increment is specified before it is built and proven before it is accepted ([ADR 051](<https://aureliusenterprise.github.io/refactor-webapp-lineage-promote/architecture/adr/051-the-conversion-proceeds-in-specified-increments/index.md>)). The checks a PR must pass:

- [ ] Semantics spec in `<project>/specs/N-M-slug/` (the [Spec Map](<https://aureliusenterprise.github.io/refactor-webapp-lineage-promote/architecture/conversion/spec-map/index.md>) says where), every rule has an id
- [ ] Every new public function has a test that names it (`@pytest.mark.covers`)
- [ ] Every rule id is named by at least one test
- [ ] Parity scenarios for the endpoints in scope pass, each citing its Atlas source (ADR 052)
- [ ] `nx affected -t lint typecheck test e2e -c ci` is green and the coverage gate holds
- [ ] Design log, Java map and deviations updated; ADR written if a business-level decision was made
- [ ] Conventional-commit title and two human approvals
