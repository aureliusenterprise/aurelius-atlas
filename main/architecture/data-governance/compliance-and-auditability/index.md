# Compliance &amp; Auditability

Compliance and auditability require evidence of how data is handled across the organization. Data lineage provides a critical foundation for meeting regulatory requirements.

## Regulatory Frameworks

| Framework | What It Requires | How Lineage Helps |
| --- | --- | --- |
| **GDPR** | Data provenance and processing transparency | Trace personal data from collection to deletion |
| **SOX** | Audit trails for financial data | Track transformations of financial records |
| **HIPAA** | Protected health information tracking | Monitor PHI movement across systems |
| **CCPA** | Consumer data access and deletion | Identify all systems holding consumer data |

## Audit Trail

The lineage graph serves as a living audit trail:

- **Data provenance** — Where did data originate and through which systems did it pass?
- **Processing history** — When did pipelines run and did they succeed?
- **Access patterns** — Which applications consume which data assets?

See [Data Lineage](<https://aureliusenterprise.github.io/main/architecture/data-governance/data-lineage/index.md>) for details on how lineage is tracked, and [Using the Lineage Graph](<https://aureliusenterprise.github.io/main/architecture/data-governance/data-lineage/lineage-visualization/index.md>) for guidance on tracing data flows for audit purposes.
