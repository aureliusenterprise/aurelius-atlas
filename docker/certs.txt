# The standalone stack's certificate manifest, read by make-certs.sh (SPS-09, DD-681).
# One line per leaf: <certs dir> <service> <SAN>... — the script issues <service>.pem and
# <service>-key.pem into that directory, beside a copy of the CA it signs with. The directory
# names match the compose pieces' certificate mounts (the stack trusts the CA by mount only,
# SPS-10); the SAN sets match each project's tls.json (the dev `nx certgen` material), with one
# addition: the edge leaf (the server's, which the proxy serves) also names $HOST, the browser
# host (SPS-02, DD-679). No other line names $HOST — an internal leaf keeps its service name and
# the loopback names it dials under today (SPS-03). A customer who brings their own CA and leaves
# (DD-681) places them at these same paths and does not run the script.
