# 7.30 Overlay and scheme platform fixes

- **Status:** in review
- **Pull request:** — (this increment's PR)
- **Records:** DD-542 (the `color-scheme` meta for the theme override, SPL-15/SPL-16),
  DD-543 (the `Modal` on the native `<dialog>`, UIC-40), DD-544 (scroll containment for the
  overlay layers, UIC-41), DD-545 (the drawer keeps `aria-modal` and marks the background inert,
  MODAL-TRAP-001), DD-546 (`AtlasTitleStrategy`, TITLE-001), DD-547 (the lineage graph's keyboard
  model, SVG-001/KEY-GRAPHIC-CLICK-NO-KEYBOARD). Relies on DD-156 (the dark ink ramp), DD-159 (the theme pre-render,
  whose script the CSP pins, CHT-112), DD-162 (the drawer's non-modal `<dialog>` and UA reset),
  DD-163 (the modal-token fallback recipe), SPL-03/SPL-04/SPL-05 (the theme modes and their
  storage), UIC-01/UIC-09 (the component shape and the additive API).

## Scope

A modern-web-guidance audit of the webapp and the ui library (the legacy-pattern scan plus a
manual pass over the overlay, focus, scroll, and scheme guides) found three platform gaps. A
second pass, run with the accessibility-agents specialists (landmarks and headings, keyboard and
focus, forms, tables and live regions, ARIA semantics, graphics and media, and composite widgets),
found a wider set of WCAG failures across the two projects. The user chose to fix every finding in
this increment rather than open follow-up increments. This increment closes all of them. It changes
no screen semantics, no REST call, and no dictionary meaning.

- **The platform color scheme (SPL-15, SPL-16).** In dark mode the app's own surfaces flip, but
  native UI (form controls, scrollbars, the pickers, the UA canvas under overscroll) stayed
  light, because nothing ever set `color-scheme`. A `<meta name="color-scheme">` now carries the
  scheme, and the brand sheet maps it back onto the CSS property.
- **The `Modal` on the native `<dialog>` (UIC-40).** The Bulma modal is hand-rolled: nothing
  focuses on open, focus escapes to the page behind, the background stays reachable, and Escape
  only works when focus sits inside. The library's own `Drawer` already rides a native
  `<dialog>`; the `Modal` now does too. Its public API and its Bulma card anatomy are unchanged
  (UIC-09).
- **Scroll containment (UIC-41).** With an overlay open, a wheel over its scrim or a gesture
  inside it scrolled the page behind. The overlay parts now contain their scroll.
- **The accessibility sweep.** The second pass found a critical failure (the lineage graph's
  nodes respond to a click only, so the keyboard cannot open an entity) and many serious ones:
  no skip link or `<main>` landmark, no document title per route, an Escape regression on the new
  dialog, the drawer's `aria-modal` claim without a real focus trap, tables with no announced
  caption, sort, selection, or page state, form errors and required marks that no reader hears,
  misused `role="menu"`, a dangling menu focus, unnamed graphics, heading-level jumps, and
  missing live-region announcements. Each rule below names one fix. The fixes ride this
  increment; the rule ids are the audit's.

It does **not** deliver: a move of the `Drawer` onto `showModal()` (DD-162 chose the non-modal
`open` attribute for the slide-out animation, and that choice stands), a change to the three
theme modes or their key (SPL-03/SPL-04 stand), any `light-dark()` re-colouring of the brand
tokens (DD-156's ramp stays the source of truth for the app's own surfaces), or a keyboard
path for the `Drawer` hold button (pointer-only by DD-348's intent, reported not changed).

## Java origin

None. These are platform mechanics of the Angular re-write (ADR 053), not ported Aurelius
behaviour. The legacy Aurelius modal used a hand-rolled overlay with the same dismissal set
that UIC-40 keeps; the promise (its card anatomy, backdrop/Escape dismissal) is unchanged.

## Deviations

No new deviation and no ledger row: nothing observable to the REST API or the ported screen
semantics changes. The accessibility sweep changes only how the same information reaches assistive
technology, never what the screens say or the calls return. Three deliberate non-changes stay as
reported findings: the `Drawer` hold button stays pointer-only (DD-348's documented intent), the
lineage connections stay pointer-only (DD-348), and the drawer keeps `aria-modal` with an inert
background rather than moving to `showModal()` (DD-545). The CSP theme-script hash moves with the
pre-render's bytes, and CHT-112's contract test pins the three nginx copies against the HTML (7.23).
The `Drawer`'s slide-out animation is unchanged, so its e2e selectors survive.

## Acceptance

Scenarios are reviewed as code; the gate is the standard one:

- `npx nx build aurelius-atlas-webapp` — the TS and template type gate.
- `npx nx test aurelius-atlas-ui -c ci` — the lib suite: the `DarkModeService` spec's meta rows
  (SPL-15), the `Modal` spec's `cancel`-event and focus-restore rows (UIC-40) plus its
  MODAL-ESC-001/MODAL-NAME-001/DLG-HEAD-001 rows, the `Drawer` spec's inert-background and Tab-wrap
  rows (MODAL-TRAP-001) and MODAL-CLOSE-001 row, the table/pagination live-region and caption rows
  (TABLE-001..006, I18N-001), the form rows (FORM-*), the composite-widget rows (ROLE-MENU-MISUSE,
  DETAILS-NAV-FOCUS, the `ModelViewer` keyboard model), and the `DataQualityPie` ALT-001 row.
- `npx nx test aurelius-atlas-webapp -c ci` — the app suite: the shell landmark/skip-link/announcer
  rows (LANDMARK-001/002, LR-003), the title-strategy rows (TITLE-001), the search-layout status
  rows (LR-001), the heading rows (HEADING-001..004), the tab-panel and tree rows
  (TAB-PANEL-WIRING, TREEITEM-WRAPPER), and `i18n-completeness.spec.ts` (every new `@@` key against
  the vendored dictionaries and both catalogues, SHL-08/UIC-04).
- `uv run pytest tests/test__charts_webapp.py` — CHT-112 with the recomputed hash.
- `npx nx lint aurelius-atlas-ui` and `npx nx lint aurelius-atlas-webapp`,

- e2e: `test__info_modal_opens_and_closes` (the `.modal` / `.modal-card-title` / delete-control
  locators are unchanged). The full webapp e2e run is the CI gate.
