# Deviations from Apache Atlas

Every behaviour of Aurelius Atlas that a client could observe and that differs from Apache Atlas
2.4.0 ([ADR 046](../adr/046-the-catalogue-keeps-its-public-contract.md)). The parity report links
each tolerated difference to its entry here; a difference without an entry is a defect.

| #     | Area           | Apache Atlas behaviour                                                                                                                                                                                                      | Aurelius Atlas behaviour                                                                                                                                                                                                                                                                                                                     | Reason                                                                                                                                           | Increment |
| ----- | -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | --------- |
| DV-01 | Notifications  | Publishes entity changes to Kafka; consumes hook messages                                                                                                                                                                   | Not supported                                                                                                                                                                                                                                                                                                                                | Out of scope ([ADR 050](../adr/050-the-system-carries-only-what-the-catalogue-needs.md))                                                         | 0.1       |
| DV-02 | Authorization  | Ranger or simple authorizer                                                                                                                                                                                                 | Simple authorizer only                                                                                                                                                                                                                                                                                                                       | Out of scope; Ranger needs its own server                                                                                                        | 0.1       |
| DV-03 | Admin          | `version` names Apache Atlas 2.4.0 and its build revision                                                                                                                                                                   | Names Aurelius Atlas, its release and its revision                                                                                                                                                                                                                                                                                           | A client must be able to tell which implementation answers                                                                                       | 0.5       |
| DV-04 | Authentication | Every endpoint except `admin/status` needs a login; the session reports the user, groups and permissions                                                                                                                    | A server configured without an OIDC issuer needs no login and its session reports no user; with an issuer configured, the endpoints demand one (AUTH-01)                                                                                                                                                                                     | Authentication (6.1) is a configuration, not a compile-time constant; an unconfigured installation stays open                                    | 0.5       |
| DV-05 | Admin          | The session's `timezones` are Java's `TimeZone.getAvailableIDs()`                                                                                                                                                           | The IANA time zone ids of the server's tz database, sorted                                                                                                                                                                                                                                                                                   | Java's list includes legacy three-letter ids the IANA database does not have                                                                     | 0.5       |
| DV-06 | Types          | A type definition's `createdBy` and `updatedBy` name the user who created and last updated it                                                                                                                               | Absent until the type endpoints that report them are ported (1.6)                                                                                                                                                                                                                                                                            | There is no login before 6.1 and no type endpoint before 1.6 either; retired with 1.6                                                            | 1.4       |
| DV-07 | Types          | The built-in model types and the patch records name the operating system account the server runs as                                                                                                                         | Name no user                                                                                                                                                                                                                                                                                                                                 | The account is an accident of deployment, and is the same for every type a process loads                                                         | 1.5       |
| DV-08 | Types          | A patch without an id is recorded, without an id, at every start                                                                                                                                                            | Is applied at every start and not recorded                                                                                                                                                                                                                                                                                                   | A record without an id cannot be found again; Atlas never matches it either                                                                      | 1.5       |
| DV-09 | Dashboards     | One process (the web application) serves both dashboards and the API from one origin; `/n` reaches `/n/` through its directory redirect, and its responses carry no hardening headers                                       | The dashboard image serves the dashboards and proxies `/api/` to the API-only server, keeping the one origin: `/n` redirects 308, and the responses carry the hardening headers of the site config — no CSP, as the vendored UI runs inline scripts and `eval` and ADR 046 keeps its behaviour                                               | The one origin is kept for the session cookie and the relative URLs; the split follows the template's serving pattern (DD-034 supersedes DD-018) | 0.6       |
| DV-10 | Authentication | The login entry point answers in the serving process: unauthenticated requests redirect to `/login.jsp` or the issuer, the form posts to `j_spring_security_check`, and logout clears only the local session and its cookie | nginx redirects unauthenticated page loads to the server's login start under `/api/atlas/auth/login` (DD-036) and serves its own login page at `/login.jsp`, where the flow lands after logout and resolves to the dashboard in use (DD-040); the form endpoint is unused and logout also ends the issuer session (AUTH-06, AUTH-10, DSH-09) | The dashboards are served by a separate process and stay untouched (ADR 046); the redirect belongs on the browser path, where it works           | 6.1       |
| DV-11 | Authentication | An expired session mid-use redirects the request, so an XHR receives the login page's HTML where Atlas's own handler expects a status                                                                                       | An unauthenticated API request is answered 401 with the Atlas error body (AUTH-04); the dashboards' 401 handler reports it                                                                                                                                                                                                                   | A JSON client cannot render a redirected login page, and a cross-origin redirect to Keycloak fails CORS                                          | 6.1       |
| DV-12 | Authentication | Only the static paths and `admin/status` are public; `admin/liveness` and `admin/readiness` need a login                                                                                                                    | `admin/liveness` and `admin/readiness` answer without a login (AUTH-02)                                                                                                                                                                                                                                                                      | Container probes and load balancers hold no session; the stack gates start-up on readiness                                                       | 6.1       |
| DV-13 | Authorization  | The session reports `atlas.entity.update.allowed` and `atlas.entity.create.allowed` from the authorizer's answer for the user                                                                                               | Both report false until the simple authorizer arrives (6.2); with 6.1 the server knows the user but not yet what the user may do                                                                                                                                                                                                             | The authorizer is its own increment (6.2); reporting false keeps the dashboard's edit paths off until policies exist                             | 6.1       |
