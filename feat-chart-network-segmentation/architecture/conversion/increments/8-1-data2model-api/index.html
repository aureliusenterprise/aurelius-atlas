Increment 8.1 — data2model API¶

Field Value
Status accepted
Author Aurelius Atlas maintainers
Date 2026-10-23
ADRs 055 (auxiliary APIs are a named data surface), 051 (increments), 049 (traceability), 052 (parity cites the reference; here the reference is Aurelius source)
Design log DD-197 (foundation), DD-209 (provider/route layout), DD-198 (no pandas: pydantic rules, plain rows), DD-132 (audience-scoped roles), DV-68 (native layout)

Objective¶

Port the legacy Aurelius m4i-data2model service — the model-extraction API the lineage graph draws on — to a FastAPI app: apps/aurelius-atlas-data2model.

POST /extract takes tabular data plus element/relation/view rules and returns an archimate3 model string the webapp's archimate3 parser ingests, plus per-record metadata. The legacy chain is lineage_model → data2model /extract (8.2 ports the caller).

The legacy implementation is a Flask app on m4i-analytics (pandas, graphviz, bokeh). Per DV-68 the analytics library is not ported: the ar3 JSON is built natively, and the archimate_process graphviz layout is replaced by a deterministic native left-to-right layout — coordinates only need to be numbers to the parser (DV-68). The port adds no pandas (DD-198): the request rules are pydantic models, the tabular data stays a plain list of row maps, and the extraction is plain Python — the legacy's pandas DataFrame was its representation, not part of the browser contract. The browser contract — the JSON body of the response and the ar3 model string's shape — is the legacy contract and is cited rule by rule.

Scope¶

In scope: the app (settings, app factory, /extract, liveness), the ar3 builder and layout, unit tests, parity scenarios read from the Aurelius source, container and e2e (Keycloak-protected, real tokens).

Out of scope: the caller (lineage_model, 8.2), the webapp lineage screen (7.x webapp track), the legacy /parse_dataset endpoint (file upload to pandas — its only caller is the legacy model-editor app, not the lineage chain; not ported), the m4i-analytics library (DV-68).

Contracts and Rules¶

The reference for every rule is the Aurelius source (ADR 055 R4): the legacy service backend/m4i-data2model/m4i_data2model/data2model.py (extract), libs/m4i-analytics/m4i_analytics/model_extractor/ExtractorLanguagePrimitives.py, .../graphs/languages/archimate/ArchimateUtils.py (to_JSON, generate_view), and m4i-analytics-extensions/m4i-graphviz-layouts (layout names).

Reference types¶

concept_type accepts the Archimate 3.0 tags the legacy ElementType enum publishes; the lineage chain uses lineage_dataset and lineage_process (both layer Other). relationship_type accepts the legacy shorthands (lr → lineage_relation, f → ar3_Flow, …). The full tables are ported as data, not as the enum machinery.

Data contracts¶

  • POST /extract — request/response per DTM-01..DTM-09; the lineage rules (4 element, 2 relation, 1 static view, DTM citations above) are the 8.2 caller's payload and are exercised as a scenario.
  • Rule models (pydantic, aurelius_atlas_data2model.rules): ExtractionRequest{data, rules{elements, relations, views}}, ElementRule, RelationRule, ViewRule, ViewNodeRule, ViewEdgeRule, MappingEntry — extra rule keys are ignored (the legacy adapters' **kwargs), null string fields are the legacy's empty string, and cross-rule references (relation source/target, view node/edge rules) are validated at parse time (DTM-11).
  • GET /liveness — 204, no auth (the container healthcheck).
  • Settings (env prefix AURELIUS_ATLAS_DATA2MODEL_): host, port (21001), log_level, tls_cert_file/tls_key_file, auth_server_url, auth_realm, auth_audience, auth_ca_file, otel_token_url, otel_client_id (otel-data2model), otel_client_secret, otel_endpoint, otel_ca_file.

Deviations (recorded in deviations.md)¶

  • DV-68 (design-level, recorded in 8.0): the ar3 model is built natively, not by m4i-analytics; coordinates are the deterministic LR layering, not graphviz positions. The port is pandas-free (DD-198) — the ar3 string's shape and the {model, metadata} body are unchanged.
  • DV-70: a null element name yields '', not the legacy 'nan' string (DTM-02).
  • DV-79: malformed input is 400, not the legacy 500 (DTM-11).
  • DV-71: the answer's content type is application/json, not Flask's text/html (DTM-01).

Test list¶

  • Unit: apps/aurelius-atlas-data2model/tests/test__extract.py (the DTM rules), test__aurelius_atlas_data2model_app.py (settings/liveness wiring), test__…_providers_auth.py/test__…_providers_telemetry.py/test__…_routes.py (the DD-209 providers and route factories, on the fake issuer).
  • Scenario (parity, read from Aurelius source — ADR 052 applied to the Aurelius reference): scenarios/lineage/extract.scenario.yaml — the 8.2 caller's fixed rules with a two-relation lineage payload, the expected {model, metadata} body read from the legacy chain's shape (coordinates masked volatile, the native layout carried as DV-68).
  • E2E: e2e/ — real container, Keycloak-minted token; 401 unauthenticated, 200 with the lineage rules; collector leg exercised by the e2e stack.

Acceptance criteria¶

  • Every rule id names a test (ADR 049 — aurelius-atlas-trace check green).
  • The ar3 string parses with the webapp's archimate3 parser expectations (DTM-09, cited).
  • Ruff, pyright, prettier, commit checks; nx test/nx e2e pass.

Delivery¶

  • Branch: feat/aux-apis-data2model (PR 2 of the 8.x chain, on 8.0).
  • M6: the first dashboard-visible surface of ADR 055; the webapp lineage screen (7.x track) consumes it unchanged.

Open questions¶

  • Element/relationship type tables: full Archimate 3.0 ported (chosen — the rules are a public API, a caller may name any type) vs the lineage pair only.
