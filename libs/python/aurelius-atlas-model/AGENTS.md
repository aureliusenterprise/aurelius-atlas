# aurelius-atlas-model

Atlas data shapes without I/O (DD-002, DD-020). This file covers wiring specific to this lib;
workspace-wide rules — including the scaffold recipe for Python libs — live in the root `AGENTS.md` and
`libs/python/AGENTS.md`.

## Layout

- `aurelius_atlas_model/typedef.py` — the typedef models (`org.apache.atlas.model.typedef`), their enums
  and the built-in type names
- `tests/` — TDM-01 to TDM-20; `tests/fixtures/` holds Atlas's `0010-base_model.json` and
  `0011-glossary_model.json`, unchanged

## Conventions

- Python attributes are snake_case; the JSON names are the Java getter names, generated by `to_camel`
  (TDM-01). A Java name `to_camel` does not produce needs an explicit alias.
- Write response bodies with `to_json()`: by alias, nulls left out, empty collections kept (TDM-02).
- A Java setter that normalises its input becomes an `_`-prefixed validator on the field, so it runs
  on reading, construction and assignment (`validate_assignment`), as the Java setter does.
- No I/O, no settings, no registry lookups: resolving type names is `aurelius-atlas-typesystem` (1.2, 1.3).

## Wiring Checklist

- Registered in root `pyproject.toml` (workspace members, dev group, `uv.sources`).
- `sonar-project.properties` and `.env.enc` (`SONAR_TOKEN`) for the CI Sonar job.
- `docs/api-reference/libs/python/aurelius-atlas-model.md` and its `mkdocs.yaml` nav entry.
